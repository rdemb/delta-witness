### Typed selector process

Each selector executes in its own child process with a deterministic command and invocation binding. Normal pass/fail requires exact typed receipt/process agreement for exactly one logical unittest.

A visible binding is not authentication. The fixed project-owned bytes are authorized because they are reviewed and synthetic, not because the child process is contained.

### Anonymous path representation

The anonymous path shape may contain only exact executed statement and arc sets. Selector, selector ID, quadrant, context, binding, and hit-count magnitude are excluded from the anonymous key but retained separately in evidence records.

Profile path comparison uses a canonical multiset. Order is non-semantic; multiplicity is semantic.

This representation preserves control-flow co-occurrence only. It is not dynamic slicing, checked coverage, data-flow provenance, condition coverage, full path coverage, or oracle influence.

### Mutation result

Only the five generated generic mutants execute. Duplicate, invalid, and not-applicable records remain non-executed.

Killed means that at least one exact profile selector produced a complete typed failure under the mutant. Survived means every exact selector in that profile passed completely. Error, timeout, missing receipt, or ambiguity remains indeterminate.

Survival does not establish equivalence. The five operators do not establish representative fault coverage or mutation adequacy.

## Residual risks

### Public merge ordering is not proof of non-inspection

Git provides a durable public sequence, not a complete private activity history. The result can claim only that the authorized reproducible workflow begins after the merged preregistration.

### Exact path shapes may be representation-sensitive

Python line tables, compiler behavior, Coverage.py arcs, entry/exit sentinels, and interpreter revisions may alter structural identities without changing intended semantics. Cross-version disagreement must remain visible.

### Structural paths do not establish oracle influence

A selector can execute a path without its executed computation affecting the assertion. Checked coverage and dynamic slicing remain stronger direct baselines for that question.

### Fixed truth table and mutants are narrow

The experiment is intentionally auditable but unrepresentative of arbitrary predicates, stateful systems, loops, exceptions, concurrency, external effects, or real authorization policies.

### Context and binding identities are forgeable

Static contexts and invocation bindings improve partition and substitution checking. They do not authenticate malicious tested code or a compromised producer.

### Integrity is not authentication

All digests are unkeyed. An actor able to replace the complete trusted chain can recompute every value.

### No operating-system sandbox

The authorized code is fixed and project-owned. The runner does not contain filesystem access, network use, process creation, resource exhaustion, dependency compromise, or host exploitation.
